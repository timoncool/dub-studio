# Решение

`speaker_count=0` сохраняет автоматический режим; 1–8 задаёт ожидаемое число голосов на всю запись. Поле принадлежит параметрам запуска конкретного проекта, сохраняется в `launch_defaults.json` и аргументах задания.

При заданном числе Sortformer остаётся единственным детектором речевых реплик. WeSpeaker, уже входящий в стек приложения, извлекает голосовые признаки из трёх самых длинных чистых реплик каждой нужной локальной метки (до шести секунд на реплику, без одновременной речи других меток). Для образцов доступны полные реплики контекстного окна, включая его перекрытие.

Уверенно раздвоенные метки одного фрагмента объединяются независимо от заданного числа: косинусная близость не ниже 0,95 и отсутствие совместной речи дольше 0,25 секунды. Это освобождает место для участника, который заговорил позже. Если различных голосов всё ещё больше заданного предела, возвращается явная ошибка. Между фрагментами выполняется совместное сопоставление с глобальными голосовыми образцами, чтобы две локальные метки не выбирали одного глобального участника независимо. Перебор по подмножествам до восьми участников выбирает назначение с максимальной суммарной близостью. Свободный голосовой слот имеет оценку 0,5; совпадение с существующим голосом ниже 0,5 не допускается. Паузы на границе фрагментов не влияют на узнавание голоса. Пороги требуют проверки на настоящих голосах; синтетические проверки подтверждают только логику назначения.

Граница владения между окнами проходит по середине перекрытия: конец предыдущего и начало следующего обрезаются до одной точки. Сначала выбираются реплики, принадлежащие окну, затем извлекаются признаки только для их меток. Метка, оставшаяся целиком в отбрасываемом контексте, не требует образца и не может остановить анализ. Финальная сборка объединяет только касающиеся или пересекающиеся реплики одного участника и сохраняет короткие подтверждённые голоса без фильтра по суммарной длительности. Автоматический режим сохраняет прежний алгоритм.

Ошибка загрузки модели или извлечения признаков возвращается явно: заданное число не подменяется автоматическим режимом или одним спикером. При одном спикере голосовые признаки не нужны. Если обнаружено меньше участников, новые голоса не создаются из ничего, а прогресс сообщает расхождение.

В кэш диаризации входят выбранное число, версия алгоритма `known-voices-v3` и полный BLAKE3-отпечаток WeSpeaker. Модель читается целиком небольшими блоками; изменение середины при одинаковом размере тоже меняет ключ. Ошибка чтения модели возвращается явно. Для автоматического режима и одного спикера WeSpeaker не читается. Кэш распознавания заданного режима зависит от ключа диаризации и её итоговой разметки: смена модели инвалидирует его даже при одинаковых репликах. REST отвергает неверное число до постановки задания. MCP включает параметр в ключ результата одношаговой транскрипции.
